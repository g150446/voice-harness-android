# EPUB リーダーモード

アプリに取り込んだ EPUB を、スマホ画面と Even G2 の両方で読む操作モード。既存の「リーダー」
（Kindle 画面を読み取って G2 へ流す）とは別物で、本そのものをアプリが持つ。Harness Node の音声で、
目次の項目を開ける。

## 使い方

1. ホーム → **EPUBライブラリ** → **EPUBを追加** でファイルを選ぶ（アプリ内にコピーされる）。
2. 本の **開く** を押すとスマホのリーダー画面が開く（前回の位置から再開）。
3. リーダー画面の **EPUBモードにする**、ホームの操作モードの **EPUB** ボタン、または音声
   「グラスモード変更 EPUB」で EPUB モードに入る。開いた本が無いと有効化できない。G2 は必須でなく、
   G2 が接続されていればその画面にも本文が出る。モードは永続化され、再起動後に復元される
   （最後に開いた本が無ければ AI 対話へ戻る）。

## G2 での読み方

- 本文はシングルタップで次のページへ進む。表示中の分の終わりが近づくと、プラグインが自動で続きを
  要求し、章をまたいでも連続して読める。本の最後では止まる。
- ダブルタップで録音（コマンド）、もう一度で確定（既存のモードと同じ）。G2 未接続でも、EPUB モード中の
  録音は常にコマンドとして扱い、LLM の対話には流れない。

## 音声コマンド（Harness Node）

| 発話 | 動作 |
|---|---|
| 「目次」「もくじ」「アウトライン」 | 番号付きの目次を G2 に出す |
| 「3番」「三番目」（目次表示中は「3」だけでも可） | 目次の3番目の項目を開く |
| 「第二章」「はじめに」「〇〇を開いて」 | 題名で項目を開く（全角半角・漢数字・かな/カナの違いは吸収） |
| 「次のページ」「前のページ」「3ページ進めて」 | チャンク単位で進む / 戻る |
| 「次の章」「前の章」 | 章単位で移動（最初の章の途中では、その章の頭へ） |

- 題名が一意に近ければすぐ開く。複数の項目が同じくらい近いときは、番号付きの候補を G2 に出すので
  「2番」のように選び直す。近い項目が無いときは「一致する項目がありません」を数秒出して、元のページへ戻る。
- 目次・候補の表示中に「次のページ」などのページ操作をすると、本文（保存位置）へ戻る。
- 目次は EPUB3 の `nav`、無ければ EPUB2 の `toc.ncx` から作る。章の途中を指す項目（`章.xhtml#id`）は
  その位置から開く。本のナビゲーション文書は本文として出さず、この番号付き目次で置き換える。
- 目次の題名（短い上位24件）を音声認識のヒントとして渡す。

## 「ページ」の意味（制限）

G2 のプラグインは表示中のページ番号を Android に報告しない。そのため Android が管理する単位は
**チャンク**（約1,000文字、段落境界で区切る。プラグインがそれを画面サイズに再分割する）。

- 「前のページ」「戻る」はチャンク単位。保存する位置も「最後に渡したチャンクの先頭」で、再開は
  そのチャンクの頭から。ページ単位の厳密な復元はしない。
- 正確にしたい場合は、プラグインに表示ページの報告を足す別作業が要る（プラグインの再パック）。

## 対象外

DRM 付き EPUB（読み込み時にエラー）、固定レイアウト、画像・表・数式の表示、縦書き表示。ルビは
親文字だけを出す。アプリ内マイクからの操作と、他アプリからの共有で開く導線は無い。

## 実機での確認（2026-09-22）

Motorola razr 50s + Even G2 で、EPUB モードのシングルタップページ送り（同一チャンク内、および
チャンク境界をまたいだ advance 要求の両方）が動作することを確認した。一度「タップしても進まない」
ように見えた事象は、BLE の切断が原因で、コード側の不具合ではなかった。BLE 接続状態
（`BleConnectionService` の接続状態表示、または再接続を待つ）を確認すること。

## 実装

`epub/` パッケージ: `EpubParser`（container → OPF → 目次）、`EpubHtmlText`（jsoup で本文抽出）、
`EpubChunker`、`EpubVoiceCommand`（`parseEpubCommand`）、`EpubReaderController`（位置と G2 への公開）、
`EpubLibrary`（取り込み・保存）、`EpubReaderHub`（`BleConnectionService` / `VoiceProcessor` との接続）、
2つの Compose Activity。G2 へは既存の `reading` 表示と advance 要求（`requestEvenG2PageAdvance`）を
使うので、プラグインの変更は不要。目次と候補は `response` 表示（4項目を1段落にまとめ、
プラグインの `paginate()` が項目の途中で切らないようにする）。
